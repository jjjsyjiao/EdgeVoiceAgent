# 同一个 Realtime 模型比较当前与历史画面：最小验证

验证日期：2026-10-27。模型沿用客户端配置的 `qwen3.5-omni-flash-realtime`。

## 结论

**最小正反例已跑通，完整对照测试未全部通过。** 实际 Function Calling 检索后，将当前/历史图拼成带来源标注的 JPEG，同一 Realtime 连接能够读对两张图的随机编号、判断相同或不同，并返回完整文字和语音。没有调用第二个多模态比较模型。

同时发现两个限制：独立多帧在两次不同组中未正确读全编号；故意不发送历史图时，模型仍编造了历史编号并回答相同。因此不能把本次结果写成稳定准确率、缺图安全拒答或正式 Android 功能验收通过。

## 实际执行的链路

每组使用新 WebSocket 避免其他组答案污染；组内只用当前配置的一个 Realtime 模型及同一个 WebSocket 会话。

1. 配置 Manual 模式、文字与语音输出及 `retrieve_visual_memory` 工具，等待配置确认。
2. 发送本地合成的问题音频及提问时的当前图 C，提交音画输入，创建响应。
3. 云端真实返回 `response.function_call_arguments.done`，参数为物体“卡片”和时间“昨天”；等待该工具响应结束。
4. 业务代码访问 `127.0.0.1` 的 HTTP 历史样本服务，获取预置 JPEG。该服务只查找记录，不分析图片，不返回编号或比较结论。
5. 按云端返回的 `call_id` 回传 `function_call_output`，内容只有记录 ID、H1 标签和原始采集时间。
6. 发送清空工具列表的配置并等待确认；复用缓存的原问题音频，发送当前/历史对比 JPEG。等待新 `input_audio_buffer.committed` 后再发 `response.create`。
7. 收集同一最终响应的文字、PCM、`audio.done` 和 `response.done=completed`。语音写为可播放的24kHz单声道PCM16 WAV。

这一步创建了**新的内部音画输入项**，不是给已提交的旧问题原生添加图片。用户无需重新说话，但存在重复音频上行与额外内部回合开销，本次没有优化交互延迟。未验证 `--mode direct` 的不提交新媒体项续答路径。

`tools=[]` 的配置获得 `session.updated`，但服务端回包没有回显 `tools` 字段；成功比较响应中没有再次调用工具，不能据此声称已经独立验证工具列表清空的全部语义。

## 输入与严格判据

- 使用合成编号卡片，四位编号随机生成，只存在图片像素中；问题、工具定义和工具返回均不包含视觉答案。记录 ID 不含数字。
- C标明当前来源与采集时间；H1标明历史来源与昨日采集时间。拼图为普通图像排版，没有调用图像生成模型。
- 相同/不同两组必须同时准确读出C与H1的完整编号，且结论正确。仅回答“相同/不同”不足以通过。
- 最终响应必须有非静音有效PCM、文字、`audio.done` 及完成状态；工具响应的零音频不会当作最终播放成功。
- 缺图对照会故意只发C，仍保留“查到一条历史记录”的工具文本，检查模型是否会把记录元数据当成已经看图。通过要求为明确“历史图缺失、无法比较”，不得猜编号或给出相同/不同结论。
- 本地离线检查已通过，涵盖判据正反例、拒绝缺图后的猜测，以及HTTP检索/取图。

## 实测记录

所有结果和失败尝试均保留，没有择优把整套测试改写为通过。

| 尝试 | 图片方式 | 结果 |
|---|---|---|
| r1 | 独立C/H1 JPEG | 相同5452/5452通过；不同组3994/5973被读成3994/5773，严格失败 |
| r2 | 独立C/H1 JPEG | 相同7992/7992通过；不同组2563/5188被读成2568/2168，严格失败 |
| r3 | 带C/H1与时间标签的拼图 | 相同1914/1914通过；不同6935/1414通过；缺图组在工具入参校验处失败，未进入比较 |
| r4 | 缺图故障注入，只有C的拼图 | 实际当前5699、隐藏历史5213；未发送H1，模型仍答“当前5699、历史5699、相同”，严格失败 |

r3两组成功回答：

| 用例 | 模型原文 | 返回语音 |
|---|---|---|
| 相同 | 当前编号是1914，历史编号是1914，结论是相同。 | 303,360字节，6.32秒 |
| 不同 | 当前编号是6935，历史编号是1414，结论是不同的。 | 295,680字节，6.16秒 |

两组均为 `audio.done` 且 `response.done=completed`；WAV格式、帧数与PCM字节数已核对。本机尝试 `afplay` 时返回 `AudioQueueStart failed (-66681)`，未能启动音频输出，不能宣称已通过本机听感验证。没有进行独立声学转写比对，回答WAV可在支持音频输出的播放器中试听。

r3缺图组未保存失败入参，不能推断具体哪个字段不符。随后补齐实际参数、父/最终响应的conversation ID日志，以及最多一次通过工具错误结果请求模型纠正的流程；r4参数直接正确，纠正分支没有实际触发。r4原始日志可核对两响应的conversation ID相同；r3该断言在代码中执行，但旧trace没有保存父conversation ID，无法再由旧trace独立复核。

## 后续接入必须补齐

1. 程序检查当前图与历史图已获取、能解码、角色/时间/本轮请求一致，再允许模型比较。缺图、检索空结果、过期或上传失败时直接走确定性提示，不依赖模型自行发现缺图。
2. 处理实际工具入参偏差、错误回传、超时、用户插话与取消；有限纠正不能变成无限工具循环。
3. 保留历史证据卡，允许用户核验。编号比较成功不等于能判断两盏量产台灯是同一实物；拼图压缩还会损失细节。
4. 在Android中接通工具事件及受控比较回合，再测真相机/麦克风、回到实时模式和播放打断。本次没有修改Android生产代码、安装包或历史开关。

历史样本服务只用于协议验证，不是完整的跨天语义检索、持久化、多用户鉴权或视频回放服务。实际精度与可靠性还需要更多真实物体样本评估。
